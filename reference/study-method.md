# Study Method

## The weekly loop

Use the same 8-10 hour loop until a module gate is met:

1. **Recall first** - write what you remember before opening notes.
2. **Read the must-know facts** - focus on decision rules, not service trivia.
3. **Build the guided path** - inspect every created resource and policy.
4. **Break one thing** - diagnose from evidence rather than guessing.
5. **Complete the challenge** - work from requirements with reduced guidance.
6. **Defend the architecture** - reject plausible alternatives explicitly.
7. **Clean up** - prove the account returned to baseline.
8. **Test and log errors** - classify misses and schedule retrieval.

Split the work across several sessions. Long passive study blocks create familiarity, not recall.

## Retrieval schedule

Revisit a new decision rule:

- At the end of the module
- In the next study cycle
- During the next phase review
- In a mixed scenario after the related module is no longer recent

Increase the interval only when you can apply the rule to a new scenario.

## The one-page rule

After each module, create one page from memory containing:

- Five decision rules
- Three common distractors
- Two failure modes
- One cost risk
- One security boundary
- One diagram

Compare it with `must-know.md`, correct it, then recreate it later without looking.

## How to review a missed question

Do not memorize the answer letter.

1. Extract every hard requirement.
2. State why your choice failed one requirement.
3. State the correct decision rule.
4. Explain why the strongest distractor is wrong.
5. Create a different scenario that uses the same rule.
6. Reattempt that concept later.

## How to know a lab is mastered

You can:

- Predict the resources and trust boundaries before deployment.
- Build the challenge without copying the guided lab.
- Diagnose a controlled failure from logs, metrics, policies, routes, or events.
- Explain cost behavior while idle and under load.
- Remove every resource and prove cleanup.
- Replace one requirement and adapt the design correctly.

## Avoid these study traps

- Watching courses without building
- Memorizing service lists without access patterns
- Taking the same practice set until the score rises
- Treating uncertain guesses as correct
- Ignoring cleanup and operations
- Studying only the strongest exam domain
- Scheduling SAP because SAA was passed
